# CLAUDE.md — orz-mdhtml

Guidance for AI agents working in this repository.

> **orz family:** this repo is one member of the orz family — before changing anything another member depends on, read the family docs via [`../CLAUDE.md`](../CLAUDE.md) (contracts, shared rules, release order, and drift ledger in `../docs/`).

## What this is

`orz-mdhtml` is "Markdown that edits itself": a document is its **text twin**
(`x.md`, orz text format 1, FC-18) and its **self-editing file** (`x.md.html`)
is `assemble(text)` — a single page that reads like a themed website and can
be edited and saved in the browser. Built on the orz-markdown carrier kit
([orz-markdown](../orz-markdown) `carrier/*`).

Two npm packages live here, **versioned in lockstep**:
- `orz-mdhtml` — the CLI and the Node library (this package).
- `orz-mdhtml-browser` — the browser engine and editor component (`browser/`):
  `orz-mdhtml.browser.js` (IIFE, `globalThis.OrzCarrier`, FC-19), the ESM build
  `esm/orz-mdhtml.browser.mjs`, `release.json`, hand-written `index.d.ts`.

## Commands

```bash
npm run build            # tsc -p tsconfig.build.json (dist/) && npm run bundle
npm run bundle           # build/bundle.ts: browser/orz-mdhtml.browser.js (bundle rule) + esm/ + release.json,
                         #   and the same IIFE + release.json into dist/ (the Node library's engine)
npm test                 # vitest: project "main" (unit, CLI, real Chrome), then project "conformance"
npm run typecheck        # tsc --noEmit over src, tests, scripts, build
npm run gen -- new x.md  # the CLI from source (tsx src/cli.ts …)
npm run clean
```

The CLI (`orz-mdhtml --help`; FC-10, inline by default, `--cdn` for the web):

```bash
orz-mdhtml new [x.md] [--title T] [--theme id] [--measure m] [--lang l] [--html] [--cdn]
orz-mdhtml assemble x.md [-o out] [--cdn]     # also: orz-mdhtml x.md
orz-mdhtml extract x.md.html [-o out]         # the exact text twin; 0.x files → upgrade
orz-mdhtml upgrade old.md.html [-o out] [--text t.md | --no-text]
orz-mdhtml inspect <file> [--json]
orz-mdhtml themes
```

Every command takes `--json` (one object on stdout), `--help`, `--force`;
exit 0 done / 1 refused or failed / 2 usage. Content (title, theme, measure,
lang, metadata) comes only from the text's header — `assemble` has no content
options. Files that could hold other work are not overwritten without
`--force` (see `src/cli.ts` guards, claim T.7).

Tests live in `tests/` and are bound to the claims in `notes/CLAIMS.md`
(`tests/claims.test.ts` fails on an unbound or unknown claim id).
`tests/global-setup.ts` runs `tsc -p tsconfig.build.json` and stages the
engine into `dist/` first (the CLI tests spawn `dist/cli.js`). The
`conformance` project (`tests/conformance.test.ts`, ~2 min of Chrome) runs
orz-markdown's carrier harness against the real carrier after the others; it
must stay conformant (45 checks, no `allowSkips`). Real-Chrome tests skip
without an installed Chrome (playwright-core, channel `chrome`) — such a run
verifies nothing "real". Still **verify generated files in a real browser**
(editing and Save need Chromium); `build/serve.cjs` is a dependency-free
static server for that.

## Architecture

- **Isomorphic core** (no Node built-ins, no clock, no randomness except
  `mintUid`; claim A.8): `src/assemble.ts` (`assemble`, `shellParts`,
  `newDocument`, re-exported kit `extract`/`readDocument`),
  `src/presentation.ts` (header `theme`/`measure` → head links, article
  class), `src/inspect.ts`, `src/legacy.ts` (`readLegacy`, `upgrade` of 0.x
  files), `src/themes.ts` (the one theme list), `src/version.ts` (generated by
  `scripts/sync-version.ts`).
- **Node only**: `src/engine.ts` finds and verifies the engine an inline file
  carries (`dist/orz-mdhtml.browser.js` + `dist/release.json`, version and
  SHA-384 checked); `src/lib.ts` is the package's main export (`assemble` /
  `upgrade` default to that engine); `src/cli.ts` is the `orz-mdhtml` bin.
- **Browser engine** `src/browser/`: `index.ts` (IIFE entry, `OrzCarrier`,
  boots an assembled file), `esm.ts`, `carrier.ts` (FC-19 API; `mountEditor`
  on the kit's editor shell); `md/` = the kind-specific renderer, read view,
  settings and `StandaloneKind`; `standalone/` + `ui/` + `engine-source.ts` =
  the KIND-INDEPENDENT startup behind the `StandaloneKind` seam, to be lifted
  into orz-markdown `carrier/app` (claim L.1 guards it). The standalone file
  warns before closing with unsaved changes (`beforeunload`, R.9); an editor
  mounted on the file via `OrzCarrier.mountEditor` is the file's (R.10).
- `build/bundle.ts` — esbuild → the IIFE/ESM, the bundle rule, `release.json`;
  `buildBrowser({ version })` builds in memory (tests, the conformance `next`).
- `examples/webapp/` + `docs/embedding.md` — the app embedding path (X.*).
- `orz-mdhtml-skills/` — the agent skill (updated in step 7).

## Conventions & gotchas

- **The text is the document.** Every save, update, "New document" and
  "Save as new copy" writes `assemble(text)` — never the live DOM.
- **Node and the browser write the same bytes** (FC-18 law 2): the Node
  library inlines exactly the bundle `npm run bundle` staged in `dist/`; a
  stale engine is refused ("run `npm run bundle`"), never inlined.
- **The browser bundle embeds orz-markdown.** To pick up parser/runtime changes,
  bump the `orz-markdown` dep, `npm install`, then `npm run build`.
- **`dist/`, `browser/orz-mdhtml.browser.js`, `browser/esm/` and
  `browser/release.json` are gitignored** build artifacts; `browser/package.json`,
  `browser/index.d.ts` and `browser/README.md` are tracked.
- **Bundle rule** (orz-markdown spec/shell-runtime.md §6): the browser bundle
  holds no `<script`/`</script` and no CR — `build/bundle.ts` rewrites `<` as
  `\x3C`, checks, then computes the SHA-384 for `release.json`. Never ship a
  bundle that skipped it (the quiet update refuses it).
- **Kit gaps** are worked around locally behind a `KIT GAP` comment and
  reported, never patched in orz-markdown from here.
- An assembled file loads its theme, KaTeX and highlight.js stylesheets from
  CDNs (an inline file carries the engine, not the styles); reading works in
  all modern browsers, **editing/Save only in Chromium**.

## Releasing (two packages, same version)

1. Bump **both** `package.json` and `browser/package.json` to the same version.
2. `npm run build` (stages `browser/orz-mdhtml.browser.js`, `browser/esm/`,
   `browser/release.json`, and the same engine into `dist/`).
3. `npm publish ./browser` (orz-mdhtml-browser) **first**, then `npm publish`
   (the CLI) — so `--cdn` URLs resolve.
4. Token: granular with **bypass-2FA** (and "create new packages" for a new
   name) in a temp `.npmrc`, **deleted after**; never commit.
5. **Network note**: IPv6 is unreliable on this machine — prefix npm/git network
   commands with
   `NODE_OPTIONS="--dns-result-order=ipv4first --no-network-family-autoselection"`.
